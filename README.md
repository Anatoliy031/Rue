# Дорога в Гузерипль

Сайт-путеводитель по маршруту Краснодар → Гузерипль. 134 места: что находится по
дороге и рядом, куда можно подъехать на обычной машине, где нужно идти пешком,
где желателен внедорожник и где требуется пропуск Кавказского заповедника.

---

## Как выложить сайт в интернет

Инструкция для человека, который не программист. Понадобится бесплатный аккаунт
на GitHub. Ничего устанавливать на компьютер не нужно.

### 1. Создайте репозиторий

Зайдите на github.com → кнопка **New repository** → придумайте имя, например
`doroga-v-guzeripl` → **Create repository**.

### 2. Загрузите файлы

На странице нового репозитория нажмите **uploading an existing file** и
перетащите туда всё содержимое этой папки. Внизу нажмите **Commit changes**.

Важно: загружайте именно содержимое папки (файл `package.json`, папки `src`,
`public`, `scripts`, `.github`), а не саму папку целиком.

### 3. Включите публикацию

В репозитории откройте **Settings** → слева **Pages** → в разделе **Source**
выберите **GitHub Actions**. Больше ничего менять не нужно.

### 4. Подождите

Откройте вкладку **Actions**. Там появится задача «Публикация сайта». Когда
рядом с ней загорится зелёная галочка (обычно 2–3 минуты), сайт готов.

Адрес будет такой:
`https://ВАШ-ЛОГИН.github.io/ИМЯ-РЕПОЗИТОРИЯ/`

Адрес подставляется автоматически из имени репозитория — руками ничего
прописывать не надо.

### Как обновить сайт потом

Загрузите изменённый файл через **Add file → Upload files** и нажмите
**Commit changes**. Сайт пересоберётся сам за пару минут.

## Как запустить у себя на компьютере

Нужен [Node.js](https://nodejs.org) версии 20 или новее.

```bash
npm install     # один раз, скачает всё необходимое
npm run dev     # запустит сайт на http://localhost:5173
npm run build   # соберёт готовый сайт в папку dist
npm run preview # покажет собранный сайт
```

## Обязательный шаг: геокодирование

**Это единственное, что нужно сделать вручную, и это важно.**

В базе намеренно оставлены пустые координаты у тех мест, где точная привязка не
была подтверждена. Сейчас таких **105 из 134** — они есть в каталоге, поиске и
подборках, но не выведены на карту. Так и задумано: лучше честный пропуск, чем
точка, поставленная наугад в центр посёлка.

Чтобы заполнить их из OpenStreetMap:

```bash
GEOCODE_CONTACT=ваш@email.ru npm run geocode
```

Скрипт работает медленно (примерно секунда на запрос — таково правило сервиса
Nominatim), проверяет, что найденная точка действительно попадает в Адыгею, и
отбрасывает совпадения из других регионов и «центры населённых пунктов вместо
самого объекта».

На выходе появятся два файла:

- `src/data/adygea_guzeripl_pois.geocoded.json` — база с найденными координатами;
- `geocoding-report.md` — отчёт: найдено точно / найдено вероятно / неоднозначно
  / не найдено.

**Сначала прочитайте отчёт.** Всё из раздела «найдено вероятно» стоит проверить
по карте. Когда убедитесь, что точки стоят правильно, скопируйте geocoded-файл
поверх `src/data/pois.json` — и места появятся на карте.

Ничего из «неоднозначно» и «не найдено» скрипт в базу не записывает.

## Проверка данных

```bash
npm run validate   # ищет ошибки в базе, запускается сам перед сборкой
npm run report     # обновляет data-report.md
npm run sitemap    # пересоздаёт sitemap.xml и robots.txt
```

`npm run validate` останавливает сборку, если в базе появилось что-то опасное
для читателя: дубль id, несуществующая ветка, координаты вне района маршрута,
координаты `[0,0]` или невозможное сочетание вроде «прямо на машине» +
«экспертная сложность».

## Где что лежит

```
src/
  data/
    pois.json          главная база — 134 места, 15 веток, 19 источников
    types.ts           типы TypeScript: POI, Branch, Source, GuideData…
    taxonomy.ts        подписи к кодам: access, difficulty, категории
    guide.ts           загрузка базы, slug, предупреждения, выборки
    route.ts           схема дороги и высотный профиль
    collections.ts     восемь готовых сценариев поездки
  components/          профиль высот, карта, фильтры, панель места
  pages/               девять страниц сайта
  hooks/               мой маршрут, медиазапросы, метаданные страниц
scripts/               validate / geocode / report / sitemap
public/                иконки, манифест PWA, service worker, 404-редирект
.github/workflows/     автоматическая публикация на GitHub Pages
```

Карточки мест нигде не прописаны в коде — всё рисуется из `pois.json`.
Чтобы добавить место, отредактируйте только этот файл.

### Добавить фотографии

Структура данных уже это поддерживает. У любого места можно указать:

```json
"images": [
  { "src": "./photos/rufabgo-04.jpg", "credit": "Автор снимка", "license": "CC BY 4.0" }
]
```

Пока фотографий нет, вместо них рисуется топографический узор, уникальный для
каждого места. Выдуманных снимков в проекте нет и быть не должно.

## Что сайт умеет

- **Главная** — высотный профиль всей дороги. Видно, что две горные ветки
  уходят вверх и обрываются: между Лаго-Наки и Яворовой поляной автомобильного
  проезда нет. Это самая частая ошибка при планировании.
- **Карта** — кластеризация, разные значки категорий, линии основной дороги и
  тупиковых веток, слой высокогорья, синхронизация со списком.
- **Каталог** — комбинируемые фильтры: как добираться, сколько времени, что это,
  участок маршрута, бесплатно/платно, с детьми, только проверенные, показать
  малоизвестные.
- **Карточка места** — доступ, где оставить машину, сколько идти, сложность,
  сезон, пропуск, деньги, риски, координаты, кнопка «Открыть в навигаторе»,
  источники и дата проверки.
- **Подборки** — восемь сценариев, от «еду и почти не хочу ходить» до
  официальных маршрутов №30В и №30Г.
- **Мой маршрут** — список сохраняется в браузере, есть ссылка для обмена и
  предупреждение, если вы смешали ветки, между которыми нет проезда.
- **Заповедник** — правила, снимок статуса маршрутов с датой проверки и ссылка
  на официальный источник.
- **Как собраны данные** — статусы достоверности, что вычислено, а что взято из
  источника, и полный список мест без координат.
- **Работает без интернета** — однажды открытый сайт остаётся доступен офлайн.
  Тайлы карты не кэшируются, но каталог, карточки и правила — да.

## Чего в проекте нет намеренно

- Выдуманных координат, цен, часов работы и состояния дорог.
- Фотографий конкретных мест, на которые нет прав.
- Отзывов.
- Инструкций по проникновению в штольни Никеля и необорудованные пещеры — только
  предупреждение об обвалах, воде, потере ориентации и возможном повышенном
  радиационном фоне.
- Мест для ночёвки вне официальных стоянок заповедника.

Цены, часы, состояние грунтовых дорог и статус горных маршрутов меняются.
Официальный источник по заповеднику — [kavkazzapoved.ru](https://kavkazzapoved.ru).
